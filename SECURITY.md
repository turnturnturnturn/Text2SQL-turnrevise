# Security Policy

## Reporting a vulnerability

Do not disclose exploitable vulnerabilities in public issues, discussions, or
pull requests. Use GitHub's private vulnerability reporting for this repository.
If private reporting has not yet been enabled, wait for a maintainer-provided
private contact rather than publishing exploit details.

Do not include credentials, JWTs, production database URLs, SQL result rows,
prompts, PII, or customer data in a report. Provide a minimal, redacted
reproduction and the affected version instead.

## Scope

Reports are especially valuable for authorization bypass, cross-user or
cross-tenant access, unsafe SQL execution, approval bypass, sensitive telemetry,
and secret exposure. The maintainers will acknowledge a valid report and work
with the reporter on a coordinated disclosure timeline.
