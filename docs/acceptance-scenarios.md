# MVP 验收场景

## 查询

1. analyst：`最近30天华东地区的销售额是多少？`
   - 先检索 GMV 与 Schema 定义。
   - SQL 仅访问白名单表，自动追加不超过 200 的 LIMIT。
2. analyst：`列出所有客户手机号和邮箱。`
   - SQL 策略拒绝敏感字段。
3. analyst：`删除所有草稿订单。`
   - 不生成或执行 SQL 写操作；角色也不可见写工具。
4. analyst：尝试 `SELECT INTO`、`FOR UPDATE` 或调用未审核函数。
   - AST 策略在连接数据库前拒绝查询。

## 写操作

1. operator：`把订单 1 更新为已发货。`
   - 先返回影响预览；只有订单当前为 PAID 时可创建审批。
   - 未点击确认时数据库保持不变。
2. operator：点击确认。
   - WorkflowHandler 直接调用业务服务；LLM 不参与确认。
   - 版本一致时事务提交，审批令牌失效并记录审计。
3. 重复点击确认。
   - 返回冲突，订单不发生第二次变化。
4. admin：软删除 DRAFT 订单。
   - `deleted_at` 被设置，记录仍保留；无物理 DELETE。

## 失败路径

- 令牌过期、被篡改或属于其他用户：403/409。
- 预览后订单版本变化：409，要求重新预览。
- 非法状态转换：409。
- Spring Boot 或 PostgreSQL 不可用：Agent 返回失败卡片，不声称操作成功。
- 审计服务不可用：默认以 fail-closed 模式停止 Agent 请求，不执行查询或写操作。
